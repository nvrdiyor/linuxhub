**Nginx** — yengil, tezkor web server va reverse proxy. Ubuntu Server'da static fayllar, dynamic backend (PHP, Node.js), va load balancer sifatida ishlatiladi.[¹](https://nginx.org/en/docs/)

<Callout type="info" title="Bu darsda nimani o'rganasiz">
- Nginx o'rnatish va boshlash.
- `sites-available` va `sites-enabled`.
- Reverse proxy — Node.js backend'ga.
- Let's Encrypt SSL avtomatik.
- Load balancing — multiple backend.
</Callout>

## 1. O'rnatish

```bash
sudo apt update
sudo apt install -y nginx

sudo systemctl enable --now nginx

# Tekshirish
sudo systemctl status nginx
curl http://localhost
# Welcome to nginx!
```

UFW'da:

```bash
sudo ufw allow 'Nginx Full'    # 80 + 443
# yoki
sudo ufw allow 'Nginx HTTP'    # 80
sudo ufw allow 'Nginx HTTPS'   # 443
```

## 2. Fayl tuzilishi

```
/etc/nginx/
├── nginx.conf              # asosiy
├── sites-available/        # barcha site'lar
│   └── default
├── sites-enabled/          # faol site'lar (symlink)
│   └── default → ../sites-available/default
├── conf.d/                 # qo'shimcha config'lar
├── modules-available/
├── modules-enabled/
└── snippets/               # qayta ishlatiladigan
    ├── fastcgi-php.conf
    └── snakeoil.conf
```

Static fayllar:

```
/var/www/html/index.html
```

Log'lar:

```
/var/log/nginx/access.log
/var/log/nginx/error.log
```

## 3. Server block (virtual host)

`/etc/nginx/sites-available/example.com`:

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name example.com www.example.com;

    root /var/www/example.com;
    index index.html index.htm;

    location / {
        try_files $uri $uri/ =404;
    }

    # Access log
    access_log /var/log/nginx/example.com.access.log;
    error_log /var/log/nginx/example.com.error.log;
}
```

Yoqish:

```bash
sudo ln -s /etc/nginx/sites-available/example.com /etc/nginx/sites-enabled/

# Default'ni o'chirish (opsional)
sudo rm /etc/nginx/sites-enabled/default

# Test sintaksis
sudo nginx -t

# Reload
sudo systemctl reload nginx
```

## 4. PHP backend (LEMP)

```nginx
server {
    listen 80;
    server_name example.com;
    root /var/www/example.com;
    index index.php index.html;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
    }

    # Static fayllar uzoq kesh
    location ~* \.(jpg|jpeg|png|gif|ico|css|js|woff2)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

## 5. Reverse proxy — Node.js

Node.js `localhost:3000`'da ishlaydi:

```nginx
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
        proxy_read_timeout 60s;
    }
}
```

WebSocket ham qo'llab-quvvatlaydi (`Upgrade` header).

## 6. SSL — Let's Encrypt (Certbot)

```bash
sudo apt install -y certbot python3-certbot-nginx

# Avtomatik — Nginx config'ni o'zgartiradi
sudo certbot --nginx -d example.com -d www.example.com

# Email kiriting, terms accept
# Avtomatik 80 → 443 redirect
```

Sertifikat:

```
/etc/letsencrypt/live/example.com/
├── fullchain.pem
├── privkey.pem
├── chain.pem
└── cert.pem
```

## 7. Yangilangan SSL server block

Certbot avtomatik shunday yaratadi:

```nginx
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name example.com www.example.com;

    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

    root /var/www/example.com;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}

server {
    listen 80;
    server_name example.com www.example.com;
    return 301 https://$host$request_uri;
}
```

## 9. Load balancing

Bir nechta backend:

```nginx
upstream backend {
    least_conn;
    server 10.0.0.10:8080 weight=3;
    server 10.0.0.11:8080;
    server 10.0.0.12:8080 backup;
}

server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

Strategiyalar:

- `round-robin` (default) — ketma-ket
- `least_conn` — eng kam ulanish
- `ip_hash` — IP asosida (session sticky)
- `weight=N` — og'irlik

## 10. Rate limiting

DDoS himoya:

```nginx
http {
    # 10 req/s, burst 20
    limit_req_zone $binary_remote_addr zone=mylimit:10m rate=10r/s;

    server {
        location /api/ {
            limit_req zone=mylimit burst=20 nodelay;
            proxy_pass http://backend;
        }
    }
}
```

## 12. Security headers

```nginx
server {
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header Content-Security-Policy "default-src 'self'" always;
}
```

## 13. Static files — yuqori performance

```nginx
location ~* \.(jpg|jpeg|png|gif|ico|css|js|woff|woff2|ttf|svg)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
    access_log off;
    sendfile on;
    tcp_nopush on;
}

# HTML — har vaqt yangi
location ~* \.html$ {
    expires -1;
}
```

## 14. Log format

Custom log:

```nginx
log_format custom '$remote_addr - $remote_user [$time_local] '
                  '"$request" $status $body_bytes_sent '
                  '"$http_referer" "$http_user_agent" '
                  'rt=$request_time';

server {
    access_log /var/log/nginx/custom.log custom;
}
```

JSON log:

```nginx
log_format json escape=json '{'
    '"time":"$time_iso8601",'
    '"remote_addr":"$remote_addr",'
    '"status":$status,'
    '"request":"$request",'
    '"bytes":$body_bytes_sent,'
    '"ua":"$http_user_agent",'
    '"rt":$request_time'
'}';
```

## 15. Eng tez-tez uchraydigan xatolar

- **`sudo nginx -t` qilmaslik** — reload buzilish.
- **`sites-enabled` symlink yo'q** — site ishlamaydi.
- **Default site o'chmagan** — ikki site bir port'da konflikt.
- **PHP-FPM socket yo'l noto'g'ri** — `php8.2-fpm.sock` versiya'siga moslash.
- **Let's Encrypt rate limit** — 5 ta sertifikat haftada (sandbox bilan test qilish).

## 16. Eng yaxshi amaliyot

- **Har vaqt `nginx -t`** — config o'zgartirilgandan keyin.
- **`sites-available` + symlink** — site'larni kontrol qilish oson.
- **HTTP/2 yoqilgan** — `listen 443 ssl http2`.
- **Strict TLS** — `options-ssl-nginx.conf` (Mozilla preset).
- **Log rotation** — `/etc/logrotate.d/nginx` default.
