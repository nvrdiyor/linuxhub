NixOS modul tizimi — `configuration.nix` ning ostida turuvchi mexanizm. Har bir modul — `{ options, config }` taqdim etadi va boshqalar bilan **avtomatik birlashadi**.[¹](https://nix.dev/tutorials/module-system/)

## 1. Modul nima?

Module — Nix funksiyasi:

```nix
{ config, lib, pkgs, ... }:

{
  options = {
    # Bu modul qaysi opsiyalarni qo'shadi
  };

  config = {
    # Bu modul opsiyalarni qanday qiymatlar bilan to'ldiradi
  };
}
```

## 2. Eng oddiy misol

```nix
{ config, lib, pkgs, ... }:

{
  options.services.myapp = {
    enable = lib.mkEnableOption "myapp service";
    port = lib.mkOption {
      type = lib.types.port;
      default = 8080;
      description = "Port to listen on";
    };
  };

  config = lib.mkIf config.services.myapp.enable {
    systemd.services.myapp = {
      description = "My App";
      wantedBy = [ "multi-user.target" ];
      serviceConfig.ExecStart = "${pkgs.myapp}/bin/myapp --port ${toString config.services.myapp.port}";
    };
  };
}
```

So'ng `configuration.nix` da:

```nix
services.myapp = {
  enable = true;
  port = 9000;
};
```

## 3. Modullar birlashishi

NixOS bir nechta modulni birlashtiradi:

- Default — `/etc/nixos/configuration.nix`.
- `imports = [ ./modul1.nix ./modul2.nix ];` — qo'shimcha.
- Nixpkgs modullari (`nixos/modules/`) — barcha standart.

Ulardagi `config` o'zaro birlashadi (`mkIf`, `mkDefault`, `mkForce` orqali).

## 4. Bilim sinovi

**Savol 1.** Modulning ikki asosiy qismi:

- a) `imports` va `exports`
- b) `options` va `config`
- c) `enable` va `disable`
- d) `input` va `output`
