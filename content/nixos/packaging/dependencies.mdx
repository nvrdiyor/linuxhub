Paket boshqa paketlarga bog'liq bo'lishi mumkin. Nix bog'liqlik turlarini farqlaydi.[¹](https://nixos.org/manual/nixpkgs/stable/#ssec-stdenv-dependencies-reference)

## 1. Asosiy turlar

| Tur | Maqsad | Misol |
|---|---|---|
| `nativeBuildInputs` | Build vaqtida kerak, runtime'da emas | `cmake`, `pkg-config`, `make` |
| `buildInputs` | Build vaqtida + linklash | `openssl`, `zlib` |
| `propagatedBuildInputs` | Build + paketning foydalanuvchilariga ham uzatiladi | `python` libraries |
| `checkInputs` | Testlar uchun (faqat `doCheck = true`) | `pytest` |

## 2. Misol

```nix
{ stdenv, fetchurl, cmake, pkg-config, openssl, zlib }:

stdenv.mkDerivation {
  pname = "myapp";
  version = "1.0";

  src = fetchurl { /* ... */ };

  nativeBuildInputs = [ cmake pkg-config ];
  buildInputs = [ openssl zlib ];
}
```

- `cmake` build vaqtida — natija binary'siga kerak emas.
- `openssl` linklanadi — runtime'da kerak.

## 3. Native vs build

**Cross-compilation** uchun farq muhim:

- `nativeBuildInputs` — **build mashinasida** (host architecture).
- `buildInputs` — **target mashinasida** (cross-compile uchun).

Standart build'da farq sezilmaydi.

## 4. propagatedBuildInputs

Agar siz Python kutubxonasi paket qilsangiz va u boshqa kutubxonalarga muhtoj bo'lsa — `propagatedBuildInputs` orqali ular sizning paketingizdan foydalanuvchilariga ham uzatiladi:

```nix
python3Packages.buildPythonPackage {
  pname = "mylib";
  version = "1.0";

  propagatedBuildInputs = with python3Packages; [
    requests numpy
  ];
}
```

## 5. Mashq

`hello` paketni `openssl` bilan birga build qiling (sun'iy misol):

```nix
{ stdenv, fetchurl, openssl }:

stdenv.mkDerivation {
  pname = "myhello";
  version = "1.0";
  src = ./.;
  buildInputs = [ openssl ];
  buildPhase = "echo 'using openssl'";
  installPhase = "mkdir -p $out && echo done > $out/done";
}
```
